# VentCalc v2.0

VentCalc v2.0 — новый C# Revit Add-in для профессиональных расчётов вентиляции. Проект создан с нуля: старый pyRevit-код не переносится и не копируется.

## Состав решения

- `VentCalc.Revit` — Revit add-in, точка входа `IExternalApplication`, команды, Ribbon и Revit-сервисы чтения модели.
- `VentCalc.Core` — расчётное ядро и модели данных без зависимости от Autodesk Revit API.
- `VentCalc.UI` — WPF-интерфейс окон плагина.
- `VentCalc.Reports` — будущая генерация Excel-файлов и отчётов.
- `VentCalc.Tests` — тесты расчётных формул и ядра.

## Целевая платформа

- Autodesk Revit 2025 x64.
- .NET 8 (`net8.0` / `net8.0-windows`).
- Visual Studio 2022.
- Конфигурация для проверки в Revit: `Debug x64`.
- Установка debug-сборки в Revit: `tools\install-debug.ps1`.

## Этап 1 — запуск add-in

После загрузки add-in в Revit создаётся вкладка **VentCalc** с двумя панелями:

### Панель «Вентиляция»

- **Расчёт** — заглушка, расчёт воздуховодов пока не реализован.
- **Инспектор** — рабочий инспектор выбранного MEP-элемента воздуховодной системы.
- **МС** — заглушка.
- **Трасса** — заглушка, подсветка пока не реализована.
- **Скорости** — заглушка, подсветка пока не реализована.
- **Настройки** — заглушка.

### Панель «Сервис»

- **Очистить** — заглушка.
- **О программе** — заглушка.

Ribbon создаётся безопасно: повторный запуск не должен создавать дубли вкладок, панелей и кнопок. Если на старте add-in возникает ошибка, Revit показывает `TaskDialog` с полным текстом исключения.

## Этап 2 — Инспектор выбранного элемента, сети, трасс и предварительного расчёта

Команда **Инспектор** читает ровно один выбранный элемент воздуховодной системы, строит связанную вентиляционную сеть по коннекторам, ищет возможные трассы внутри сети, выполняет предварительный расчёт потерь на трение по воздуховодам трасс и показывает результат в WPF-окне с прокруткой.

Поддерживаемые категории:

- `OST_DuctCurves`
- `OST_DuctFitting`
- `OST_DuctAccessory`
- `OST_DuctTerminal`
- `OST_MechanicalEquipment`

Если ничего не выбрано или выбрано больше одного элемента, появится сообщение:

```text
Выберите ровно один элемент воздуховодной системы.
```

Если выбран элемент неподдерживаемой категории, появится сообщение:

```text
Выберите элемент воздуховодной системы.
```

Инспектор показывает:

- блок выбранного элемента: `ElementId`, категорию, имя, имя типа, семейство, систему, тип системы и уровень;
- найденные параметры выбранного элемента: расход воздуха, размер, диаметр, ширину, высоту, длину, комментарии, `ADSK_Наименование`, `ADSK_Размер_УголПоворота`;
- коннекторы выбранного элемента: номер, `ConnectorType`, `Domain`, `Direction / FlowDirectionType`, `Shape`, радиус, ширину, высоту, `IsConnected`, количество `AllRefs`, Id подключённых элементов;
- блок связанной сети: количество элементов, воздуховодов, фитингов, арматуры, терминалов/решёток, оборудования, открытых коннекторов, найденных связей и список элементов сети;
- для каждого элемента сети: `ElementId`, категорию, тип, размер, расход, систему и подключённые элементы;
- блок **Трассы сети**: тип системы, направление, причину выбора направления, стартовые/конечные кандидаты, игнорируемые заглушки, предупреждения, всего трасс и список трасс;
- для каждой трассы: номер, `StartElementId`, `EndElementId`, `TotalElementCount`, `DuctCount`, `FittingCount`, `AccessoryCount`, `TerminalCount`, `EquipmentCount`, длину воздуховодов в мм/м, расход и цепочку `ElementId` через стрелку;
- блок **Предварительный аэродинамический расчёт трасс**: для каждой трассы длину воздуховодов, скорость, Re, λ, динамическое давление, удельные потери, потери на трение и предварительно критическую трассу по трению.

## Сборка и запуск в Revit 2025

### Сборка вручную через Visual Studio

1. Откройте `VentCalc.sln` в Visual Studio 2022.
2. Выберите конфигурацию **Debug x64**.
3. Убедитесь, что установлен Autodesk Revit 2025 и доступны ссылки:
   - `C:\Program Files\Autodesk\Revit 2025\RevitAPI.dll`
   - `C:\Program Files\Autodesk\Revit 2025\RevitAPIUI.dll`
4. Выполните **Build → Build Solution**.
5. После сборки основной файл add-in находится здесь:
   - `VentCalc.Revit\bin\x64\Debug\net8.0-windows\VentCalc.Revit.dll`

### Установка debug-сборки в Revit

Рекомендуемый способ установки — PowerShell-скрипт:

```powershell
powershell -ExecutionPolicy Bypass -File tools/install-debug.ps1
```

Скрипт делает следующее:

1. Проверяет, что `Revit.exe` закрыт. Если Revit запущен, выводит `Закройте Revit перед установкой VentCalc.` и останавливается.
2. Собирает `VentCalc.sln` в конфигурации **Debug x64** через MSBuild.
3. Создаёт папку установки:
   - `C:\Users\user\AppData\Roaming\Autodesk\Revit\Addins\2025\VentCalc`
4. Очищает содержимое папки установки.
5. Копирует туда все файлы из:
   - `VentCalc.Revit\bin\x64\Debug\net8.0-windows\`
6. Создаёт или обновляет manifest-файл:
   - `C:\Users\user\AppData\Roaming\Autodesk\Revit\Addins\2025\VentCalc.addin`
7. Записывает в `VentCalc.addin` полный путь к сборке:

```xml
<Assembly>C:\Users\user\AppData\Roaming\Autodesk\Revit\Addins\2025\VentCalc\VentCalc.Revit.dll</Assembly>
```

> Скрипт использует `%APPDATA%`, поэтому на машине с другим именем пользователя путь будет автоматически соответствовать текущему Windows-профилю.

После установки запустите Revit 2025 и проверьте вкладку **VentCalc** на Ribbon.

## Как проверить Инспектор в Revit

1. Откройте модель Revit с воздуховодами или вентиляционными семействами.
2. Выберите ровно один элемент одной из поддерживаемых категорий: воздуховод, фитинг, арматуру, решётку/терминал или механическое оборудование.
3. Нажмите **VentCalc → Вентиляция → Инспектор**.
4. Проверьте WPF-окно с блоками выбранного элемента, связанной вентиляционной сети, трасс и предварительного аэродинамического расчёта.
5. Проверьте блок **Трассы сети**: для приточной системы стартом может быть оборудование или открытый магистральный конец, а концами — терминалы/решётки.
6. Убедитесь, что заглушки отображаются в элементах сети, но попадают в **Игнорируемые заглушки** и не являются `StartElementId`/`EndElementId`.
7. Для системы без оборудования проверьте предупреждение `Оборудование не найдено; используется открытый магистральный конец.`
8. В блоке предварительного расчёта проверьте, что таблицы содержат только воздуховоды, а фитинги и терминалы остаются только в цепочке трассы.
9. Для ориентира: 3600 м³/ч в воздуховоде 600x300 даёт скорость около 5.56 м/с.
10. Выберите фитинг из той же сети и снова нажмите **Инспектор** — список сети и найденные трассы должны остаться теми же.
11. Если в сети есть разрыв, проверьте счётчик открытых коннекторов и стартовые/конечные кандидаты.
12. Для проверки валидации выбора запустите команду без выбора, с несколькими выбранными элементами и с элементом неподдерживаемой категории.

## Роли узлов для поиска трасс

Перед выбором стартов и концов элементы сети классифицируются по ролям:

- `TerminalCandidate` — `OST_DuctTerminal`;
- `EquipmentCandidate` — `OST_MechanicalEquipment`;
- `Cap` — заглушки из `OST_DuctFitting` / `OST_DuctAccessory`, если имя, тип или семейство содержит `Заглушка` или `Cap`;
- `OpenEndCandidate` — элемент с открытым коннектором без реального соседнего вентиляционного элемента, но только если это не терминал и не заглушка;
- `InlineDuct`, `Fitting`, `Accessory` — обычные элементы соответствующих категорий.

Заглушки не используются как стартовые или конечные точки трасс. Для приточной системы без оборудования открытый магистральный конец используется как стартовый кандидат.

## Как определяется направление трасс

- Если `SystemType` содержит `Приточный`, `Приток` или `Supply`, сеть считается приточной: стартовые точки — оборудование или открытый магистральный конец, конечные точки — терминалы/решётки.
- Если `SystemType` содержит `Вытяжной`, `Вытяжка` или `Exhaust`, сеть считается вытяжной: стартовые точки — терминалы/решётки, конечные точки — оборудование или открытый магистральный конец.
- Если тип системы определить нельзя, Инспектор пишет `Направление системы определено приблизительно` и использует fallback: терминалы считаются одной стороной, оборудование/открытые концы — другой стороной.

## Предварительный аэродинамический расчёт

Расчёт выполняется только для элементов `OST_DuctCurves`, которые входят в найденные трассы. Фитинги, арматура и терминалы пока не попадают в таблицу расчёта потерь. Используются настройки по умолчанию: плотность воздуха `1.2 кг/м³`, динамическая вязкость `0.0000181 Па·с`, шероховатость `0.0001 м`.

В Инспектор выводятся:

- расход в м³/ч и м³/с;
- длина воздуховода в метрах;
- площадь сечения;
- эквивалентный/гидравлический диаметр;
- скорость;
- Reynolds;
- коэффициент трения λ;
- динамическое давление `Pv`;
- удельные потери `R`, Па/м;
- потери на трение `R·l`;
- предварительно критическая трасса по максимальным потерям на трение.

Местные сопротивления ζ и потери на фитингах пока явно не учитываются. Если для воздуховода не найден расход, размер или длина, Инспектор показывает warning и продолжает работу.

## Ограничения текущего этапа

- Расчёт давления пока предварительный: учитываются только потери на трение в воздуховодах.
- Excel и отчёты пока не реализованы.
- Подсветка трассы, скоростей и очистка подсветки пока не реализованы.
- Местные сопротивления ζ, потери на фитингах, балансировка и подбор вентилятора пока не реализованы.
- Старый pyRevit-код не переносится и не копируется.
- Чтение параметров зависит от доступности стандартных или пользовательских параметров в конкретной модели Revit.
