# VentCalc v2.0

VentCalc v2.0 — новый C# Revit Add-in для профессиональных расчётов вентиляции. Проект создан с нуля: старый pyRevit-код не переносится и не копируется.

## Состав решения

- `VentCalc.Revit` — Revit add-in, точка входа `IExternalApplication`, команды, Ribbon и Revit-сервисы чтения модели.
- `VentCalc.Core` — расчётное ядро и модели данных без зависимости от Autodesk Revit API.
- `VentCalc.UI` — WPF-интерфейс окон плагина.
- `VentCalc.Reports` — будущая генерация Excel-файлов и отчётов.
- `VentCalc.Tests` — тесты расчётных формул и ядра.

## Целевая платформа

- Autodesk Revit 2025 x64.
- .NET 8 (`net8.0` / `net8.0-windows`).
- Visual Studio 2022.
- Конфигурация для проверки в Revit: `Debug x64`.
- Установка debug-сборки в Revit: `tools\install-debug.ps1`.

## Этап 1 — запуск add-in и компактный Ribbon

После загрузки add-in в Revit создаётся вкладка **VentCalc** с одной панелью **Вентиляция**. Ribbon больше не копирует старый pyRevit-набор кнопок: основные функции перенесены в единый рабочий центр.

На Ribbon остаются только кнопки:

- **VentCalc** — открывает главное окно **VentCalc Center**.
- **Скорости** — открывает небольшое окно будущей подсветки скоростей; применение подсветки пока отключено.
- **Настройки** — открывает отдельное окно настроек расчёта.
- **Очистить** — заглушка будущей очистки подсветки.
- **О программе** — краткая информация о VentCalc v2.0.

Отдельные кнопки **Инспектор**, **Расчёт**, **МС** и **Трасса** больше не выводятся на Ribbon. Их логика остаётся в коде для отладки и постепенно переносится внутрь **VentCalc Center**. Ribbon создаётся безопасно: повторный запуск не должен создавать дубли вкладок, панелей и кнопок. Если на старте add-in возникает ошибка, Revit показывает `TaskDialog` с полным текстом исключения.

## Этап 2 — Инспектор выбранного элемента, сети, трасс и предварительного расчёта

Команда **Инспектор** читает ровно один выбранный элемент воздуховодной системы, строит связанную вентиляционную сеть по коннекторам, ищет возможные трассы внутри сети, выполняет предварительный расчёт потерь на трение по воздуховодам и местных сопротивлений по фитингам/терминалам/оборудованию трасс и показывает результат в WPF-окне с прокруткой.

Поддерживаемые категории:

- `OST_DuctCurves`
- `OST_DuctFitting`
- `OST_DuctAccessory`
- `OST_DuctTerminal`
- `OST_MechanicalEquipment`

Если ничего не выбрано или выбрано больше одного элемента, появится сообщение:

```text
Выберите ровно один элемент воздуховодной системы.
```

Если выбран элемент неподдерживаемой категории, появится сообщение:

```text
Выберите элемент воздуховодной системы.
```

Инспектор показывает:

- блок выбранного элемента: `ElementId`, категорию, имя, имя типа, семейство, систему, тип системы и уровень;
- найденные параметры выбранного элемента: расход воздуха, размер, диаметр, ширину, высоту, длину, комментарии, `ADSK_Наименование`, `ADSK_Размер_УголПоворота`;
- коннекторы выбранного элемента: номер, `ConnectorType`, `Domain`, `Direction / FlowDirectionType`, `Shape`, радиус, ширину, высоту, `IsConnected`, количество `AllRefs`, Id подключённых элементов;
- блок связанной сети: количество элементов, воздуховодов, фитингов, арматуры, терминалов/решёток, оборудования, открытых коннекторов, найденных связей и список элементов сети;
- для каждого элемента сети: `ElementId`, категорию, тип, размер, расход, систему и подключённые элементы;
- блок **Трассы сети**: тип системы, направление, причину выбора направления, стартовые/конечные кандидаты, игнорируемые заглушки, предупреждения, всего трасс и список трасс;
- для каждой трассы: номер, `StartElementId`, `EndElementId`, `TotalElementCount`, `DuctCount`, `FittingCount`, `AccessoryCount`, `TerminalCount`, `EquipmentCount`, длину воздуховодов в мм/м, расход и цепочку `ElementId` через стрелку;
- блок **Предварительный аэродинамический расчёт трасс**: для каждой трассы длину воздуховодов, скорость, Re, λ, динамическое давление, удельные потери, потери на трение, таблицу местных сопротивлений и предварительно критическую трассу по сумме трения и местных сопротивлений.

## Этап 3 — VentCalc Center

**VentCalc Center** — основное WPF-окно проектировщика вентиляции. Оно открывается кнопкой **VentCalc** и загружает выбранную систему через уже существующие Revit-сервисы чтения элемента, сети, трасс, геометрии воздуховодов и местных сопротивлений.

Верхняя панель окна содержит:

- **Загрузить выбранную систему**;
- **Обновить**;
- **Выбрать стартовый элемент в Revit**;
- **Выбрать критическую трассу в Revit** — пока отключено;
- выбранный `ElementId`, имя системы и тип системы.

Вкладки **VentCalc Center**:

1. **Система** — сводка сети и `DataGrid` элементов: `ElementId`, категория, роль, размер, расход, длина, система, подключённые элементы и предупреждения.
2. **Проверки** — диагностика модели: открытые коннекторы, отсутствие оборудования, игнорируемые заглушки, воздуховоды без расхода/размера/нормальной длины, непонятные МС и подозрительные скорости.
3. **Трассы** — направление системы, причина выбора направления, стартовые/конечные кандидаты, заглушки, предупреждения, таблица трасс и цепочка выбранной трассы.
4. **Расчёт** — предварительная критическая трасса, предупреждение о предварительном расчёте и таблица воздуховодов выбранной трассы.
5. **Местные сопротивления** — таблица МС выбранной трассы; кнопки записи/принятия ζ пока отключены, `Обновить МС` перезагружает систему.
6. **Отчёт** — заготовка будущего Excel-экспорта и текстовый debug-отчёт.
7. **Настройки** — параметры воздуха, шероховатость, запас и пороги скоростей.

Настройки сохраняются в `%APPDATA%\VentCalc\settings.json`. Сейчас они применяются к предварительному расчёту при загрузке/обновлении системы. Запись параметров в Revit, Excel и финальная подсветка пока не выполняются.

## Сборка и запуск в Revit 2025

### Сборка вручную через Visual Studio

1. Откройте `VentCalc.sln` в Visual Studio 2022.
2. Выберите конфигурацию **Debug x64**.
3. Убедитесь, что установлен Autodesk Revit 2025 и доступны ссылки:
   - `C:\Program Files\Autodesk\Revit 2025\RevitAPI.dll`
   - `C:\Program Files\Autodesk\Revit 2025\RevitAPIUI.dll`
4. Выполните **Build → Build Solution**.
5. После сборки основной файл add-in находится здесь:
   - `VentCalc.Revit\bin\x64\Debug\net8.0-windows\VentCalc.Revit.dll`

### Установка debug-сборки в Revit

Рекомендуемый способ установки — PowerShell-скрипт:

```powershell
powershell -ExecutionPolicy Bypass -File tools/install-debug.ps1
```

Скрипт делает следующее:

1. Проверяет, что `Revit.exe` закрыт. Если Revit запущен, выводит `Закройте Revit перед установкой VentCalc.` и останавливается.
2. Собирает `VentCalc.sln` в конфигурации **Debug x64** через MSBuild.
3. Создаёт папку установки:
   - `C:\Users\user\AppData\Roaming\Autodesk\Revit\Addins\2025\VentCalc`
4. Очищает содержимое папки установки.
5. Копирует туда все файлы из:
   - `VentCalc.Revit\bin\x64\Debug\net8.0-windows\`
6. Создаёт или обновляет manifest-файл:
   - `C:\Users\user\AppData\Roaming\Autodesk\Revit\Addins\2025\VentCalc.addin`
7. Записывает в `VentCalc.addin` полный путь к сборке:

```xml
<Assembly>C:\Users\user\AppData\Roaming\Autodesk\Revit\Addins\2025\VentCalc\VentCalc.Revit.dll</Assembly>
```

> Скрипт использует `%APPDATA%`, поэтому на машине с другим именем пользователя путь будет автоматически соответствовать текущему Windows-профилю.

После установки запустите Revit 2025 и проверьте вкладку **VentCalc** на Ribbon.

## Как проверить VentCalc Center в Revit

1. Откройте модель Revit с воздуховодами или вентиляционными семействами.
2. Выберите ровно один элемент одной из поддерживаемых категорий: воздуховод, фитинг, арматуру, решётку/терминал или механическое оборудование.
3. Нажмите **VentCalc → Вентиляция → VentCalc**.
4. Проверьте окно **VentCalc Center** с вкладками **Система**, **Проверки**, **Трассы**, **Расчёт**, **Местные сопротивления**, **Отчёт**, **Настройки**.
5. На вкладке **Трассы** проверьте блок трассировки: для приточной системы стартом может быть оборудование или открытый магистральный конец, а концами — терминалы/решётки.
6. Убедитесь, что заглушки отображаются в элементах сети, но попадают в **Игнорируемые заглушки** и не являются `StartElementId`/`EndElementId`.
7. Для системы без оборудования проверьте предупреждение `Оборудование не найдено; используется открытый магистральный конец.`
8. На вкладках **Расчёт** и **Местные сопротивления** проверьте, что таблица воздуховодов содержит только `OST_DuctCurves`, а фитинги, терминалы и оборудование попадают в отдельную таблицу местных сопротивлений.
9. Для ориентира: 3600 м³/ч в воздуховоде 600x300 даёт скорость около 5.56 м/с.
10. Выберите фитинг из той же сети и снова нажмите **VentCalc** — список сети и найденные трассы должны остаться теми же.
11. Если в сети есть разрыв, проверьте счётчик открытых коннекторов и стартовые/конечные кандидаты.
12. Для проверки валидации выбора запустите **VentCalc** без выбора, с несколькими выбранными элементами и с элементом неподдерживаемой категории.

## Роли узлов для поиска трасс

Перед выбором стартов и концов элементы сети классифицируются по ролям:

- `TerminalCandidate` — `OST_DuctTerminal`;
- `EquipmentCandidate` — `OST_MechanicalEquipment`;
- `Cap` — заглушки из `OST_DuctFitting` / `OST_DuctAccessory`, если имя, тип или семейство содержит `Заглушка` или `Cap`;
- `OpenEndCandidate` — элемент с открытым коннектором без реального соседнего вентиляционного элемента, но только если это не терминал и не заглушка;
- `InlineDuct`, `Fitting`, `Accessory` — обычные элементы соответствующих категорий.

Заглушки не используются как стартовые или конечные точки трасс. Для приточной системы без оборудования открытый магистральный конец используется как стартовый кандидат.

## Как определяется направление трасс

- Если `SystemType` содержит `Приточный`, `Приток` или `Supply`, сеть считается приточной: стартовые точки — оборудование или открытый магистральный конец, конечные точки — терминалы/решётки.
- Если `SystemType` содержит `Вытяжной`, `Вытяжка` или `Exhaust`, сеть считается вытяжной: стартовые точки — терминалы/решётки, конечные точки — оборудование или открытый магистральный конец.
- Если тип системы определить нельзя, Инспектор пишет `Направление системы определено приблизительно` и использует fallback: терминалы считаются одной стороной, оборудование/открытые концы — другой стороной.

## Предварительный аэродинамический расчёт

Расчёт по трению выполняется только для элементов `OST_DuctCurves`, которые входят в найденные трассы. Местные сопротивления считаются отдельной таблицей для не-воздуховодов трассы: фитингов, арматуры, терминалов и оборудования. Используются настройки по умолчанию: плотность воздуха `1.2 кг/м³`, динамическая вязкость `0.0000181 Па·с`, шероховатость `0.0001 м`.

В Инспектор выводятся:

- расход в м³/ч и м³/с;
- длина воздуховода в метрах;
- площадь сечения;
- эквивалентный/гидравлический диаметр;
- скорость;
- Reynolds;
- коэффициент трения λ;
- динамическое давление `Pv`;
- удельные потери `R`, Па/м;
- потери на трение `R·l`;
- местные сопротивления `Z = ζ · Pv`;
- источник ζ: `Комментарии`, `Рекомендовано` или `Не найдено`;
- предварительно критическая трасса по максимальной полной потере `трение + местные`.

Для ζ в первую очередь читается параметр `Комментарии`: поддерживаются форматы `z=0.35`, `ζ=0.35`, `zeta=0.35`, `Z=0,35`, `ζ = 1,2`. Если значения в комментарии нет, используется рекомендованная таблица первого этапа: отводы по углу, переходы, тройники/врезки, клапаны, решётки, зонты, дефлекторы и заглушки. Если для воздуховода или местного сопротивления не хватает данных, Инспектор показывает warning и продолжает работу.

## Ограничения текущего этапа

- Расчёт давления пока предварительный: учитываются потери на трение в воздуховодах и местные сопротивления по комментариям/рекомендациям.
- Excel и отчёты пока не реализованы.
- Подсветка трассы, скоростей и очистка подсветки пока не реализованы.
- Сложная геометрия тройников/переходов пока не разбирается точно; если ζ не задана в комментариях, используется упрощённая рекомендованная оценка.
- Старый pyRevit-код не переносится и не копируется.
- Чтение параметров зависит от доступности стандартных или пользовательских параметров в конкретной модели Revit.

## Диагностика ошибок VentCalc Center

Команда **VentCalc** защищена от необработанных исключений при запуске окна. Если при создании окна, загрузке ViewModel, WPF Dispatcher или чтении сети возникает ошибка, Revit должен показать `TaskDialog` **VentCalc — ошибка** и оставить путь к лог-файлу.

Логи пишутся сюда:

```text
%APPDATA%\VentCalc\logs\
```

Основные файлы диагностики:

- `ventcalc_launch_yyyyMMdd_HHmmss_fff.txt` — smoke-check этапов запуска: `Command started`, `Settings loaded`, `ViewModel created`, `Window created`, `ShowDialog started`, `ShowDialog closed`.
- `ventcalc_error_yyyyMMdd_HHmmss_fff.txt` — полный `Exception.ToString()`, stack trace, inner exception и версия Revit.

Если `%APPDATA%\VentCalc\settings.json` повреждён, VentCalc переименует его в `settings_corrupted_yyyyMMdd_HHmmss.json`, загрузит настройки по умолчанию и покажет warning в окне.
